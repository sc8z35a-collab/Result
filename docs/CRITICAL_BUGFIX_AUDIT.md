# Result 追加不具合修正 20件

前回の80件がマージされた `main` の `a22f52f` を起点に調査しました。C01〜C20は `tools/regressions.test.mjs` と `tools/ui-regressions.test.mjs` のテストIDに対応します。

## P0 致命的 — 起動・描画の停止（5件）

| ID | 症状 | 修正 |
| --- | --- | --- |
| C01 | 素材画像や一覧の配信が応答を返さないと、読込画面から進めない | 画像と一覧の待機時間をそれぞれ8秒に制限し、時間切れでは代替素材に切り替える |
| C02 | 空または水面の画像が欠けると、互換描画も初期化できない | 欠けた空・水面の画像を生成したグラデーションで補う |
| C03 | 地形の素材一覧が404、破損、または素材画像と不一致だと、マップが起動しない | 素材一覧と画像の寸法を検証し、読み込めない場合も地形の色・形状と生成した標識で描画する |
| C04 | WebGLのテクスチャ確保に失敗しても、戻り値を確認せずプレイ可能扱いになる | GLのエラーを確認し、失敗したテクスチャを解放して互換描画へ切り替える |
| C05 | WebGPUから非同期の描画エラーが返った後も、HDR面がゲーム画面を覆い続ける | HDRを無効化して描画面を隠し、下のゲーム画面を表示する |

## 検証結果

- 追加の同一20テストを修正前後で実行し、修正前は20件すべてで失敗、修正後は20件すべて成功。
- `npm test --prefix tools` で既存80件を含む100件すべて成功。
- `node tools/verify.mjs` で360 Hzのシミュレーション、3v3・1v2・1v1の完走、武器・AI・描画に関する既存の検証が成功。
- 空・水面・地形素材を利用できない状態で、互換描画のマップと一人称視点を854 × 480で描画。
- `python tools/test_gpu.py` でMesaのOpenGL ES 3.2上でシェーダー11組がコンパイル・リンクに成功。

回帰テストにはNode.js 24、DOM・IndexedDBの互換実装、Canvasのソフトウェア実装を使用しました。実機スマートフォンと実物のHDRディスプレイでの検証は未実施です。
